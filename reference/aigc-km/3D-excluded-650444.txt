AI摘要: **文章摘要**  
本文介绍了腾讯混元团队开源的HY-Motion 1.0——首个基于DiT架构的10亿参数文生动作模型，旨在解决复杂自然语言指令下的3D角色动画生成难题。文章详细阐述了模型在数据构建、语义对齐、架构设计和强化学习方面的创新，并通过评测数据与生成案例验证了其在动作覆盖度、时序逻辑和细粒度控制上的突破性表现。

**文章重点总结**  
1. **核心突破**：  
   - 首创10亿参数DiT动作生成架构，通过大规模数据训练解决复杂语义还原问题。  
   - 在SSAE（语义结构自动评测）指标达到78.6%，指令跟随能力远超现有SOTA模型。  

2. **关键技术体系**：  
   - **数据引擎**：融合单目视频动捕、光学动捕和艺术家手K资产，构建3000小时标准化动作数据；通过“VLM初标+人工校验+LLM扩写”实现高质量语义标注，覆盖200+动作类别。  
   - **生成管线**：定制Prompt Engineering模块（基于Qwen3-30B-A3B），将模糊指令转化为精确的动作描述与时长，提升生成可控性。  
   - **模型架构**：采用“双流→单流”DiT设计，结合非对称掩码机制与窗口注意力，确保长时序动作的稳定性和连贯性。  
   - **训练范式**：首次将RLHF引入动作生成领域，通过“预训练→SFT→DPO+GRPO强化学习”三阶段优化物理真实感与人类审美对齐。  

3. **生成效果验证**：  
   - 复杂时序逻辑：支持连续动作转换（如“行走→突然停止→环顾四周”）；  
   - 广域动作覆盖：涵盖日常行为、体育竞技、游戏角色等高难度动作；  
   - 细粒度控制：实现肢体局部动作精准生成（如“挥手时左手插口袋”）。  
   - 评测数据对比：在动作质量6大维度（运动、体育、户外活动等）平均得分3.43，全面领先竞品（DART: 3.11；LoM: 3.06）。  

4. **开源生态**：  
   - 开放1B/0.46B模型权重、推理代码及GUI工具，已应用于AI游戏开发（ComfyUI工作流）和视频生成控制（KLING运动控制器）。  
   - 社区反馈显示动作流畅性与物理合理性达“世界级最强”水平。

正文: 一、概述
2025年12月30日，腾讯混元团队正式开源了 HY-Motion 1.0，一款基于DiT架构的十亿参数量级的3D角色动画生成模型。

图片引用: https://km.woa.com/asset/0001000226010025f0421a2916493c01?height=1079&width=2538

HY-Motion1.0 生成的动作

而在生成式 AI 领域，文生动作（Text-to-Motion）也因高质量数据的稀缺与计算范式的局限，长期处于“小模型”阶段，这类模型在面对复杂的自然语言指令输入时，很难做出创作者希望得到的正确动作。近年来，也有不少研究开始尝试通过大语言模型扩展词表的方式来做动作生成，这类模型虽然能将模型尺寸扩展到了较大的规模，但由于采用了离散的动作Tokenizer，生成的动作质量往往并不理想。
HY-Motion 1.0的发布，旨在探索在大规模数据和参数的加持下，模型在动作生成任务中的潜力与边界。作为首个将 DiT 架构扩展至 1B 参数量级的动作生成模型，我们并未止步于架构层面的探索，而是将重点聚焦于数据规模与质量的平衡以及评估体系的创新。我们希望通过 1B 参数量的模型容量，配合 LLM 范式的精细化训练，解决复杂语义下的生成难题。结果证明，我们的模型在动作覆盖度和语义对齐能力上，确实迈出了坚实的一步。

二、核心技术：
HY-Motion 1.0 的背后，并非单一的算法创新，而是一套完整的数据与训练工程体系。
1. 数据引擎：冰山之下的“笨功夫”
大规模、高质量的数据是训练1B参数模型的基础，为此，我们构建了一套标准化的数据处理管线，最终沉淀出总计超过3000 小时的动作数据。

图片引用: https://km.woa.com/asset/00010002260100f5d0f7b331d640d701?height=647&width=1692

HY-Motion1.0 数据处理流程图

多源数据的融合： 我们深知单一数据源的局限性，因此整合了三类数据：单目视频动捕数据，提供最丰富的动作种类和场景多样性；光学动捕数据，精度极高，但场景受限；艺术家手K资产，来自游戏制作管线，虽然数量少，但具备极高的美学质量和表现力。我们希望通过多种来源的数据来平衡模型的泛化能力与生成质量。

数据清洗与标准化： 为了让模型更好地进行学习，我们将所有数据重定向到同一套骨骼标准上。 随后，数据通过了一系列自动化过滤工具：去重、异常姿态/速度/位移剔除、静止片段移除，以及关键的严重滑步剔除。 最后，所有数据被标准化为 30fps，并在坐标系上统一对齐的切片数据。

VLM + LLM 的标注闭环： 为了解决语义对齐，我们设计 “渲染 -> VLM 初标 -> 人工校验 -> LLM 结构化扩写”这样一套复杂的打标流程。我们先将其基于 SMPLH 模型渲染为视频，再送入 Gemini-2.5-Pro 等 VLM 模型生成初步描述；针对渲染视频可能丢失语义的问题，我们引入人工环节修正错误、补全细节；最后利用LLM对文本进行结构规范化和多样性扩充，避免模型对特定句式过拟合。

极致的动作覆盖：这使得我们的数据涵盖了从日常行为、体育竞技到游戏格斗等 200+ 细分动作类别，为模型的泛化能力打下了最坚实的基础。

2. 生成管线：让模型听懂复杂指令
用户的输入往往很随意（比如“跳个舞”），但模型生成需要精确的语义与时序引导。为此，我们设计了一个专门的 LLM Prompt Engineering 模块来做用户Prompt改写及动作时长估计，类似于充当“动作导演”的角色。
数据合成： 为了训练这个 Prompt Engineering，我们构建了一个 {User Prompt, Optimized Prompt, Duration} 的三元组数据集。我们利用 Gemini-2.5-Pro 模拟了大量真实、随意甚至模糊的User Prompt，并将其与数据集中高质量的Optimized Prompt及真实时长对齐。

两阶段微调： 我们基于 Qwen3-30B-A3B 进行了定制化训练。在 SFT 阶段，模型通过监督学习的方式学习如何将模糊指令转化为我们需要的内容。随后，为了进一步提升泛化性能，我们进一步进行GRPO强化学习训练，利用更强大的 Qwen3-235B 作为 Reward Model，从语义一致性和时序合理性两个维度对Prompt Engineering的输出进行打分与优化。

最终， Prompt Engineering 会将用户的中文/模糊指令转化为英文动作描述和精确时长，显著提升了生成的可控性。

HY-Motion1.0 框架

3. 模型设计：DiT + Flow Matching
在核心生成架构上，我们采用了 Diffusion Transformer (DiT) 结合 Flow Matching。

图片引用: https://km.woa.com/asset/000100022601002b4452ccca3f424301?height=1111&width=2187

HY-Motion1.0 模型结构

双流混合架构： 参考 HunyuanVideo 的设计，我们采用了“双流（Dual-stream）→ 单流（Single-stream）”的结构。在双流阶段，动作 Latent 和文本 Token 独立处理，通过 self-attention 进行交互；在单流阶段， 两者拼接为统一序列，进行深度的多模态融合。

长时序稳定性： 为了解决长序列生成容易出现的崩坏问题，我们引入了非对称掩码机制，强制“动作看文本，文本不看动作”，防止了扩散过程中的噪声回流污染文本语义，确保了语义引导的纯粹性；另外我们认为动作动力学需要满足局部连续性，所以我们还采用了窗口注意力，这强迫模型专注于局部的动力学连贯性，确保了动作在时间轴上的连贯性，缓解了传统模型动作做一半突然鬼畜的现象。

4. 全流程训练：RLHF 注入指令执行力
我们将 LLM 领域的 RLHF 范式完整迁移到了动作生成中，完整跑通了 “Pre-train -> SFT -> RLHF” 的三阶段训练：

图片引用: https://km.woa.com/asset/00010002260100f2b569d13a0d44d801?height=267&width=1394

HY-Motion1.0 训练范式

Large-scale Pretraining：在 3000 小时全量数据上进行大规模预训练，让模型“见多识广”，学会各种动作的基本范式。

High-quality Fine-tuning：筛选出 400 小时的精标高质量数据进行微调，显著减少了动作抖动和滑步，提升画质。

Reinforcement Learning：我们设计了 “DPO + Flow-GRPO” 的两阶段强化学习策略：
DPO：为了对齐人类的感官审美，我们构建了 9,228 对高质量的偏好数据（Winner/Loser）。通过 DPO，我们最大化优胜样本与失败样本之间的似然差。这一步主要解决动作像不像的问题，大幅提升了生成的 Pass Rate。

GRPO：为了解决 DPO 难以处理的硬约束，我们进一步设计了一个语义约束+物理约束的奖励函数，进一步降低了模型的物理真实感不足的问题。

三、生成结果展示
得益于参数规模带来的容量优势，HY-Motion 1.0 在 SSAE（语义结构自动评测）指标上达到了 78.6%，指令遵循能力远超SOTA模型。
（注：SSAE 本质上是利用 Video-VLM 进行自动化评测。该方案将“文本-动作对齐”转化为视频问答任务：先将 Prompt 拆解为若干细粒度的判断题（如“是否在踢腿”、“是否在挥臂”），再调用 VLM 对生成动作的渲染视频进行逐项验证，以此量化模型对复杂语义的还原能力。）

四、开源与共建
