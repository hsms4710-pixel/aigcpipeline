1. **背景与挑战**  
   - 动捕动画每帧均为关键帧，单点修改会导致跳帧问题，修复需调整连续帧的骨骼数据（每帧涉及4-6根骨骼×4个四元数通道）。  
   - 传统脚本工具仅能处理简单穿模，复杂动作（如网球发球）需AI接管检测、修改、验证全流程。  

2. **AI工具链核心技术**  
   - **穿模检测器**：精确扫描碰撞骨骼、位置及严重度，提供量化数据（如"帧70：右前臂与躯干碰撞面积30%”）。  
   - **视觉反馈系统**：三视图合并渲染+多帧拼接截图，帮助AI理解空间姿态（例：调整骨骼旋转值后截图验证手臂外展效果）。  
   - **动作语义理解**：AI通过骨骼曲线（F-Curve）识别动作阶段（如网球发球5阶段），并依据阶段特性制定差异化修复策略。  
   - **智能编辑能力**：  
     - 关键帧精简：将100帧动捕数据压缩至8个关键帧（保留阶段边界帧）；  
     - 四元数通道协同编辑：支持多骨骼批量偏移（例：右臂Z通道-0.35+右前臂X/Y通道联动调整）；  
     - 快照回滚机制：实现秒级“保存→试错→回滚”循环。  

3. **全流程修复机制**  
   七阶段标准化流程：  
   ```plaintext  
   理解动作结构 → 环境准备 → 精简关键帧 → 方向探测 → 策略偏移 → 迭代验证 → 质量收尾  
   ```

     - 数据层：穿模帧归零、曲线单调性检查（避免锯齿）；  
     - 视觉层：多视角截图判断动作连贯性与合理性。

图片引用: https://km.woa.com/asset/0001000226030068e2aa54a6a24f5302?height=1680&width=1256

穿模及3D动作曲线示意

1.动捕动画的"每帧关键帧"问题

传统手K动画，一个发球动作可能只需要 5-8 个关键帧，动画师精心设定好起始、极值、收尾姿态，中间帧由曲线插值自动生成。但 2D 视频转 3D 骨骼动画的方案完全不同——视频识别是逐帧提取姿态的，输出的动画每一帧都是关键帧。假设是30FPS，3秒的动画可能就是90个关键帧。

这意味着你无法简单地"调某一帧让它不穿模"，因为改了这一帧，前后帧的值还是原来的，动画会在修改处产生突变跳帧。要改就得改一整段连续的帧，而一段穿模可能涉及20-40帧，每帧有4-6根骨骼，每根骨骼4个四元数通道——这就是上千个数值的联动调整。团队内主要由非动画背景的开发同学负责动作调整，缺乏动画基础，往往一个动作需要耗费数小时才能达到预期的效果。

2.尝试1：大模型编写脚本工具，将穿模骨骼按照法线方向进行调整，远离穿模切面

这个方案在部分简单的动作上有不错的效果，但是涉及到复杂的动作，特别是发球、击球这种多姿态动作，几乎不可用，简单的策略不可能匹配复杂的动作。不是要AI来定策略，人来执行脚本，而是AI来接管检测、修改、回滚、验证全流程。于是团队转变思路，思考如何让直接大模型来解决问题。

3.尝试2：引入大模型，但如何提供必需的能力？

穿模修复不是一个纯文本问题，大模型看不到 效果，作为一个空间类的问题，不知道球拍穿进了头部还是手肘穿过了躯干，也不知道当前帧的骨骼姿态是什么样的，更不知道调整某个骨骼的四元数通道+0.1在视觉上意味着什么。

需要解决的核心问题是：如何构建一个信息桥梁，让大模型装上眼睛"看到"穿模、配置大脑"理解"骨骼运动、增加双手"操作"关键帧、并"验证"修复效果？

二、工具链搭建

图片引用: https://km.woa.com/asset/0001000226030060a677bec9014a4602?height=1024&width=1024

1.定位穿模

最开始考虑让大模型抽样截图来判断是否穿模，同时确认修复策略，但实际测试发现，对于细微的穿模，大模型难以发现，于是制定明确的分工：工具提供精确信息，大模型依据精确信息进行下一步决策。穿模检测工具可以精确到每一帧的碰撞面数量，判断发生碰撞的骨骼和面，截图对大模型的价值不在于判断有没有穿模，而在于判断修复后的姿态是否自然。

2.装上眼睛

穿模检测解决了"有没有穿模"的问题，但修复动画不能只看数据。大模型需要回答很多视觉层面的问题：

- 调整后的手臂姿态自然吗？还是变形了？

- 球拍的朝向合理吗？像不像在发球？

- 整个动作的连贯性如何？有没有突然的抖动或卡顿？

这些问题没有精确的数值标准，必须靠"看"来判断。那如何“看”呢？最开始做了不少尝试，例如动画曲线、骨骼旋转角度等，但实践下来发现文本对于空间的表达能力太弱，于是考虑直接截图的方案，但由于动画本身包含多帧，如果让单帧、单视角截图，会导致模型反复的调用工具来执行。因此在设计截图工具时，支持3视图合并渲染、多帧拼接渲染，帮助大模型更高效的分析。

实际修复中的典型用法是这样的：

大模型："我需要探测 RightArm 的 ch3 通道在帧 70 的旋转方向"

→ 施加 +0.5 大幅偏移

→ 截取帧 70 的三视图

→ 看截图：手臂向身体内侧收拢了

→ 判断：ch3 正方向 = 内收，要避碰需要取反方向（外展）

截图在这个过程中充当了大模型的"眼睛"——它无法直觉理解四元数的旋转方向，但它可以通过"试一下然后看效果"来建立理解。这和人类动画师的工作方式其实是一样的，只不过大模型的"试一下"只需要几秒钟。

3.配置大脑

图片引用: https://km.woa.com/asset/0001000226030055a7eb2755364bad01?height=1024&width=1024

穿模检测让大模型知道"哪里坏了"，视口截图让它看到"长什么样"，但要真正修好动画，大模型还需要理解这个动作在做什么。这一点在实际修复中给了我们最大的惊喜。

我们给大模型提供了骨骼的动画曲线数据（F-Curve）——每根骨骼在每个关键帧上的四元数旋转值、值域范围、变化趋势。原本只是为了让它知道"当前值是多少、该调多少"，但大模型拿到这些数据后，做了一件我们没有预期的事情：它自动识别出了动作的阶段结构。

以发球动作为例，大模型读取右臂骨骼链的旋转曲线后，给出了这样的分析：

例如 根据 RightArm 四元数旋转曲线的变化趋势，发球动作可分为5个阶段：

- 阶段1（帧 0~25）：预备持球，手臂在腰侧，曲线平稳

- 阶段2（帧 25~55）：抛球上举，主旋转通道单调递增

- 阶段3（帧 55~72）：引拍蓄力，手臂后展至最高点

- 阶段4（帧 72~88）：挥拍击球，主通道急速反转，变化率最大

- 阶段5（帧 88~100）：随挥收拍，曲线逐渐回落趋于平稳

它是怎么做到的？本质上，大模型在做的是对曲线形状的语义理解。

动画曲线上的局部极值点（方向转折的地方）天然对应着动作的阶段边界——手臂从上举转为下挥的那一帧，就是旋转曲线从递增转为递减的拐点。识别曲线的单调性变化，就能把动作切分成有意义的阶段。

这个能力带来了三个实际价值：

i.修复策略更精准。 不同阶段对修复的容忍度完全不同。引拍蓄力阶段臂移动相对缓慢，修复偏移量可以稍大，动作不容易看出变化；而挥拍击球阶段是高速运动，曲线变化率极大，同样大小的偏移量会导致明显的视觉差异。大模型理解了这一点后，会自动对不同阶段采用不同的修复力度。

ii.精简关键帧更合理。 视频动捕输出动画每帧都是关键帧，然而这个动画可能动画师只会设置两个关键帧，因此存在大量冗余的数据，删掉中间的帧不会影响动画效果。但阶段边界上的帧是关键姿态，删掉会破坏动作结构。大模型识别出阶段边界后，精简操作就知道哪些帧必须保留、哪些帧可以安全删除。在我们的发球动画中，RightArm 从原始的100个关键帧精简到了8个，且动作形态几乎无损。

iii.曲线质量验证有了标准。 修复穿模后，怎么判断曲线有没有被修坏？如果大模型知道"帧72~88是挥拍阶段，主旋转通道应该单调递减"，那修复后它就能自动检查这一段的曲线是否仍然单调。如果出现了方向反转（值突然上升再下降），就说明引入了锯齿——即使穿模检测显示 0 碰撞，动画播放时也会出现肉眼可见的卡顿抖动。

实际上我们把这个能力固化到了修复流程中。每次修复开始前，大模型会先做一次"动作结构分析"，输出各阶段的帧范围和主要运动通道。这份分析结果贯穿整个修复过程——精简时用它确定保留帧，调整时用它控制力度，验证时用它检查单调性。

换句话说，曲线数据给了大模型理解动作的能力，而动作理解反过来指导了修复的每一步决策。这不是我们预先编程的规则，而是大模型从数据中自然涌现出来的推理能力——它看到一条从低到高再到低的曲线，就知道这是一次"举起-放下"的动作，进而推断出什么样的修复方式不会破坏这个动作的意图。

4.配置双手

有了穿模检测（定位问题）、视口截图（看到效果）、曲线分析（理解动作），大模型已经具备了完整的感知和认知能力。但它还缺最关键的一环——动手能力。

我们需要让大模型直接编辑 Blender 中的动画曲线，而不是生成一段脚本让人去执行。这个"双手"的设计，踩了不少坑。

i.需要修复的关键帧太多

这是最先遇到的障碍。动捕输出的动画每帧都是关键帧，200 帧的动画就有 200 个关键帧密密麻麻排列在曲线上。当大模型尝试修改其中一帧的值来消除穿模时，整体效果较差。

所以"动手"之前必须先做一件事：精简关键帧，把密集的固定点减少到只剩关键姿态。 我们提供了两个层级的精简工具：

- 全局精简：分析整条曲线，识别并删除对曲线形状贡献不大的冗余帧。一个 100 帧的动捕曲线通常能精简到 6~10 个关键帧，且动作形态几乎无损

- 区域精简：只对穿模段进行精简，保留入口帧、峰值帧、出口帧三个控制点，其余全部删除。这样穿模段内只剩 3 个"固定点"，大模型调整任何一个都能有效改变这一段的曲线形状

ii.核心编辑能力
精简完成后，大模型就可以有效地编辑曲线了。我们提供了四种基本操作：

修改关键帧：大模型可以对指定骨骼、指定通道、指定帧施加增量偏移（delta 模式），也可以直接设定绝对值。支持批量操作，
并且在修改完成后，立即进行三视图截图，返回当前的骨骼姿态让大模型快速验证修复效果。

插入关键帧： 在指定帧处把当前的插值姿态固化为一个新的关键帧。这在两种场景下使用：一是在穿模段中间插入额外的控制点来约
束曲线形状；二是在修复区域的边界帧插入锚点，防止后续的精简操作影响到边界外的正常动画。

删除关键帧： 支持批量删除。通常和精简配合使用，清理掉不再需要的冗余帧。
设置插值模式：关键帧之间的过渡方式直接影响动画的流畅性。线性插值是直线连接，动作看起来机械僵硬；贝塞尔插值是曲线连接，动作更平滑自然。但贝塞尔差值在稀疏关键帧之间可能产生过度的弧线弯曲（超调），反而让穿模更严重。所以大模型会先用 线性插值验证修复效果，确认无穿模后再切换贝塞尔插值做最终的平滑处理。

iii. 快照回滚
就像专业的动画师在调整骨骼动画一样，会先对骨骼进行调整，然后回滚，再确认最终合理的调整方向和调整数值。因此增加快照保存及回退机制。
穿模修复的试错率非常高。四元数旋转通道的方向在不同帧是不同的，大模型必须先试探才能确认正确方向；偏移量需要根据穿模严重程度估算，估大了姿态变形，估小了穿模残留。每一次尝试都可能走错方向。有了快照，试错成本从"分钟级"降到"秒级"，大模型可以放心地在几秒内完成"保存→尝试→看效果→回滚"的循环，这对探测通道方向和逼近最佳偏移量至关重要。

iv.多骨骼协同操作

修复穿模很少是"调一个值就解决"的事情。一段典型的弧线穿模修复，大模型需要在同一轮操作中协同编辑多根骨骼的多个通道：

一次典型的修复操作：

1. RightArm ch3（Z通道）：帧 61、70、83 统一施加 -0.35 → 主力，承担 60%

2. RightForeArm ch1（X通道）：帧 61、70、83 施加 +0.25 → 辅助，承担 25%

3. RightForeArm ch2（Y通道）：帧 61、70、83 施加 +0.10 → 辅助，承担 15%
如果这三步分开执行、分开验证，每一步单独看效果都不够——主力通道只能消除 60% 的穿模，大模型会误判为"偏移量不够"然后继续加大，最终导致单通道偏移过大、姿态变形。所以我们提供了批量操作接口，让大模型在一次调用中同时修改多根骨骼的多个通道，然后整体验证效果。

5.验证修复

第一层：数据验证（客观） 1. 穿模检测 → 穿模帧数归零
2. 曲线单调性检查 → 主运动通道在挥拍阶段没有方向反转（无锯齿）

3. 关键帧间距检查 → 相邻关键帧曲线是否发生大幅跳变

这些能排除"明显不自然"的情况——曲线尖峰、锯齿、跳变，但不能判断"看起来自然不自然"。

第二层：截图判断（主观）

1. 手臂姿态有没有明显变形 → 避免可以规避穿模，导致动作异常

2. 球拍朝向是否合理 → 判断是否符合对应动作，满足人体运动学

3. 连续帧之间的姿态变化是否连贯 → 避免动作出现抖动，不连续

这些能让大模型结合相关知识，分析整体动作是否流畅自然。

三、动作修复流程

Skill 中定义的完整修复流程分为七个阶段，每个阶段有明确的目标、操作步骤和判断标准：

阶段二：环境准备（快照 + 穿模检测）

阶段七：质量验证与收尾

大模型截取动画段内的首帧、中间帧、末帧截图，将动作划分为明确的阶段。比如一个发球动作会被划分为：预备持球 → 抛球上举 → 引拍蓄力 → 挥拍击球 → 随挥收拍。

阶段边界帧 = 曲线上的方向转折点 = 真正有意义的关键帧。这个分析结果会贯穿后续的所有步骤——精简时保留阶段边界帧，修复时根据阶段特性控制力度，验证时检查阶段内的曲线单调性

四、skill维护经验

除了观察、思考、执行外，也需要让大模型自身进行反思和总结，对于频发的问题不是手动调整prompt，人工分析根因的效率很低，因为我们不在修复的上下文里。 大模型才是那个执行了每一步操作、看到了每一个中间结果的角色。我们改变了维护方式：修复完成后（无论成功还是失败），直接让大模型自己分析这次修复过程中的问题。

不是让它笼统地"总结经验"，而是问具体的问题：

- "这次修复从开始到完成用了多少轮操作？哪些轮次是无效的？为什么？"

- "有没有某个步骤反复执行了 3 次以上？卡在什么地方？"

- "如果重新做一遍，哪些步骤可以跳过或合并？"

- "你觉得缺少什么工具或信息，导致某个判断不得不靠试错？"

Skill中定义了安全规则和常见的问题列表，在安全规则中制定调整数值大小的参考、穿模度过高时使用多骨骼协同修复、值域安全值检查等等。常见问题里有历史的一些错误经验，将错误及经验整体变成结构化的内容，给予大模型一定的前提和约束，在修复穿模的同时也能保证动作的自然和流畅。通过这个方式，原有大模型对一个动作分析及修复需要1小时以上，缩短至目前的15分钟。

五、现状及展望

1.耗时问题
目前在使用单个大模型的前提下，修复依旧需要近15分钟的时间，时间主要耗费在每个关键帧的修复尝试和回滚快照。预计随着skill的经验不断调整，能进一步缩短时间。

2.token成本情况
在token花费上，和穿模帧区间数、动画帧数相关，以发球动作为例的总输入token为211.7万，输出token为2.9万。

3.动作质量
部分动作修复后，需要人工再调整一下速度，需要再对skill进一步优化。在动作优化后，调整区间的动作细节与专业动作仍有差距。
