正文: 随着数字阅读的普及，用户对“听小说”的需求正迅速增长。有声内容不再只是文字的“附属形式”，而正在成为新的主流消费方式。然而，传统人工录制方式虽然音质优良，却难以支撑平台级的内容扩张：单本录制成本高、周期长，且音色类型有限，无法满足用户对多样化声音体验的期待。为此，QQ AI 团队构建了一套自动化、多音色的有声小说生产管线，实现了从小说文本到高质量有声书全流程智能的生成。这套系统已在手Q阅读场景落地，支撑了数以万计的章节网络小说的有声化生产。本篇文章将重点分享我们在构建有声小说自动化生产系统过程中，所遇到的三个关键技术难题及其解决思路：

1. 角色对白归属人识别，让“谁在说话”更准确。在网络小说中，人物众多、对话密集，且常出现代词省略、隐含主语等复杂表达。若对白归属不准确，不仅会破坏听感连贯性，还会削弱角色代入感。我们针对这一问题，设计了多层级对白识别与角色绑定LLM Agent工作流，综合利用上下文语义、叙述结构与人物特征，实现对白归属的高精度识别，为多音色合成提供了稳定的角色映射基础。

2. Speech Token 缓存 & 重复感知采样解码，让“短句语音合成”更自然。小说朗读往往以句为单位进行分段合成，但短文本TTS常面临韵律不稳、语气突兀的问题，容易有明显的的抽卡“问题”，基于LLM构建的自回归语音合成模型在推理短文本时解码不稳定，所以会导致在合成一些短文本的音频小概率不是很自然。为此，我们设计并采取了Speech Token缓存 + 重复感知采样解码（Repetition Aware Sampling）的协同策略。

3. TTS 推理加速，让低成本网络小说高批量生产成为可能。自回归TTS模型虽在音质与韵律自然度上表现突出，但串行解码的特性导致推理效率低，难以支撑海量文本的快速批量合成。为兼顾音质与成本，我们探索了投机解码（Speculative Decoding）和对vLLM batch推理进行适配，在不显著牺牲音质的前提下，将生成效率提升数倍，从而真正实现“低成本、高效率”的大规模生产目标。

一、 对白归属工作流，让“谁在说话”更准确。

在网络小说中，人物众多、对话密集，且常出现代词省略、隐含主语等复杂表达。若对白归属不准确，不仅会破坏听感连贯性，还会削弱角色代入感。应该使用声音体现出角色的特质，是充满童真的美少女，还是豪气万丈的铁血男儿。如何使声音最适合角色形象，需要构建准确的角色画像，才能为角色匹配出合适的音色，让听书过程更有沉浸感。因此项目启动初期，我们希望输入一个章节的内容给大模型，大模型能够一次性输出以下内容：

1. 角色

2. 角色的对白列表

3. 角色特征信息（性别，性格，年龄等）

经过一段时间的尝试和测试，很难达到满意的效果。大模型适合处理专一的任务，当任务目标有多个且输入的文本过长时，大模型很难完美的遵循指令。于是我们采用分步骤地构建 agent 工作流的方式拆解任务：

1. 提取出角色名

2. 角色进行入库处理

3. 提取出角色的对白

4. 无名角色处理（路人角色）

图片引用: https://km.woa.com/asset/00010002251100d311b6fe1beb487a01?height=206&width=1546

1. 角色提取

首先我们让大模型先按照指定的格式，将角色信息提取出来，包括本章节内出现的角色名，角色体现出的性格特征，性别，年龄等，角色的职位，角色的别名，角色的简介描述（例如角色的身份，角色的经历，角色的职位等等）。

2. 角色入库与去重

当大模型提取出本章节的角色信息后，有可能数据库里已经存在该角色了。第一层可以使用名字对角色进行去重，如果找到库里已经存在了角色，需要将角色的每个维度的数据信息进行更新。

如果库里没有找到角色，那么为了防止出现同一个角色，名字不同的情况下，我们需要通过RAG数据库，检索角色的资料，查看是否有相似度比较高的角色。检索出相似度最高的几个角色后，通过大模型分析，判断角色是否新增。最终根据大模型的结果，决定是否要新增角色，已经要重新更新RAG数据库中角色的资料。

图片引用: https://km.woa.com/asset/00010002251100c84128b513ba45c701?height=1382&width=1104

3. 对白提取与情感标注

当角色信息具备了之后，再进行对白提取，对白提取需要采用“核心对白句”+上下文的数据格式提供给模型，让模型根据角色信息，以及上下文信息，判断出这句对白的归属，这样子下来，整个对白归属的正确率就会大大提升。

角色的对话应该是具备感情色彩的，所以这里一同提取出了对白的情绪，作为后续的TTS阶段的情感参数。

图片引用: https://km.woa.com/asset/0001000225110091d1a57a96b243ae01?height=1046&width=498

4. 无名角色的处理

小说中常常会出现一些没有角色归属的声音，通常是属于路人的，如果我们笼统的将所有路人都视为同一个人，那就会很奇怪，所以我们这里要把每个章节内的路人信息做相应的区分处理，要区分出不同的路人，以及他们的性别。我们将路人的对白列表，以及小说的原文输入给大模型，让大模型区分出不同路人的对白。

由于这里大模型有时无法遵循将输入的内容原样输出的指令，所以我们要采用文本相似度计算的方式，来匹配路人旁白的归属。

图片引用: https://km.woa.com/asset/0001000225110025fa1b3ba2ac40f001?height=1312&width=1396

通过以上Agent工作流，系统能够逐步构建精细的角色画像，为语音合成提供准确的音色与情感依据，最终增强听书体验的沉浸感。

二、 Speech Token 缓存 & 重复感知采样，让“短句合成”更自然

如下图所示，现代零样本TTS系统采用自回归解码架构，其工作流程为：首先将连续的语音波形通过向量量化编码器转换为离散的Speech Token序列，然后基于Transformer等自回归模型，在给定文本和提示音频对应的Speech Token序列的条件下，逐个预测待合成文本对应的Speech Token序列，最后通过解码器将预测的Speech Token序列转换回连续的语音波形。

图片引用: https://km.woa.com/asset/00010002251100f90fd378245d454201?height=744&width=1184

在小说朗读这类应用中，通常以小说的句子为单位进行文本分段合成。然而，短文本TTS常面临韵律不稳、语气突兀的问题，容易出现明显的“抽卡”现象。究其原因，主要是当前模型的训练语料多基于中长音频构建，对短音频的覆盖相对不足，导致基于LLM的自回归语音合成模型在短文本推理时解码不够稳定，从而在部分短文本合成中表现不够自然。而模型的训练与迭代优化往往周期较长，难以快速响应业务需求。对于长音频，若TTS解码出现Bad Case，通常可借助ASR模块进行有效质检并触发重新推理；但在短文本场景下，现有ASR系统往往难以准确识别短音频的转录结果，导致质检难度较大。

在 QQ 有声小说合成实际业务中，常见的短文本可以大致分为 2 类：一类是语气词单字，例如“哈”，“嘿”，“呀”，“呵”等语气类的文字，另外一类是人物对白类的短文本，例如“好的”，“谢谢”，“受死吧”，“没问题”，“道友，别过”。

对于第一类语气短字，我们主要通过设置 Speech Token 缓存方式，如果检测到语气短字，则不通过LLM进行解码，而是直接使用已经完成Token缓存的文字，直接通过将人物的音色提示音频和Cache Token通过解码器进行语音波形合成。这样可以直接避免模型的概率抽卡不稳定的问题，保证每个语气词都可以合成稳定的声音。

对于第二类人物对白类的短文本，我们主要参考VALL-E 2论文中的重复感知采样（Repetition Aware Sampling）方法，对于对白短文本的LLM解码策略进行了优化。具体而言，在模型推理阶段，我们根据当前生成的语音Token序列动态调整采样方式：若检测到连续重复的Token比例超过预设阈值，则临时切换为随机采样(Random Sampling)以打破潜在循环；否则保持使用top-p采样，确保输出的稳定性。同时，针对短文本长度特征，我们结合输入文本的音素数量动态约束最大和最小Token生成数，避免因序列过短或过长导致韵律失调。该方法在保持音色一致性的同时，显著提升了短文本合成的自然度与稳定性。

三、 自回归 TTS 模型推理加速，让“生成速度”匹配规模生产

如今的 zero shot TTS系统主要分为自回归与非自回归两类技术路线：自回归方法通过逐个预测Speech Token实现高自然度语音合成，但受限于串行解码导致速度较慢；非自回归方法则并行生成全部Token以提升推理效率，但往往在语音自然度上有所妥协。当前主流系统多采用自回归解码架构，其工作流程为：首先将连续的语音波形通过向量量化编码器转换为离散的Speech Token序列，然后基于Transformer等自回归模型，在给定文本和提示音频对应的Speech Token序列的条件下，逐个预测待合成文本对应的Speech Token序列，最后通过解码器将预测的Speech Token序列转换回连续的语音波形。

从下图的耗时统计可以看出，TTS 模型的自回归解码占据了整个语音合成流程的近 70%的耗时，文本语音的编码，以及最后的波形合成，耗时占比只有 30%左右，因此解码加速是至关重要的一部分。

图片引用: https://km.woa.com/asset/00010002251100d1af67c1ebd341f701?height=732&width=684

为了提高LLM模型的解码效率，投机解码(Speculative Decoding)最早由谷歌团队在[1,2]中被提出。其方法可以概括为由一个小模型一次猜一批可能的结果，再由大模型并行地验证这些结果是否要接受。为了实现加速有声书的合成效率，实现更高吞吐的的TTS，我们借鉴谷歌团队的投机解码算法，在原始TTS的Speech-LLM上构建了一个更浅层小参数轻量化的Draft模型，这个Draft模型的网络结构和原始LLM保持一致，只是将Transform layer 的层数从 24层降低到了 8 层，并且其网络的初始参数完全继承自其原始模型。

图片引用: https://km.woa.com/asset/0001000225110029ddc4404e5c4ba901?height=1010&width=2192

在模型训练的过程中，我们将同时训练原始模型和轻量化的模型，并通过 KL散度进行约束，期望两者的logit分布保持一致，在模型的推理过程中，我们使用 “轻量草稿模型生成候选 + 目标模型并行验证” 的策略进行LLM 的解码，具体推理解码如下：

1. 候选 token生成：Draft草稿模型基于输入提示（文本 + 语音 token 拼接），自回归生成 3个候选语音 token。

2. 并行验证：将候选 token 输入目标模型，目标模型并行计算每个 token 的验证概率分布，避免逐 token 处理。

3. token 筛选与补全：使用 tolerance factor 参数判断是否接受候选 token，若不满足接受条件，从目标模型中重新生成 token，如果满足接收条件，则使用 Draft 模型的 token 输出结果。

通过引入投机解码，最终在 NMOS（语音质量指标）仅降低 0.5%（从 3.96 降至 3.94）、几乎不影响听觉体验的前提下，实现了推理效率 1.4 倍提升，相关优化我们也整理成论文投稿录用于语音领域顶会 InterSpeech 2025 [3]。随后我们对Speech LLM 的推理进行vLLM适配，进一步优化了服务部署的资源利用率。通过利用vLLM先进的PagedAttention技术与高效的Batch批处理机制，我们的系统能够在单次推理中并行处理多个语音合成请求，显著提升了GPU利用率并降低了单位计算成本。

经实际业务场景验证，该方案成功将合成成本控制在0.3元/万字的行业领先水平，为大规模有声书合成场景提供了兼具高效性与经济性的解决方案。

四、 总结与展望

本篇文章，由kaynliu和 autozhang 共同编写。主要介绍了QQ AI 团队在构建手Q阅读低成本、多音色有声小说智能生产管线的实践中，我们主要通过攻克对白归属识别、短句语音合成自然度以及TTS推理加速这三大技术难题，成功搭建了一套高效、自动化的有声内容生成系统。该系统不仅显著提升了角色对白归属的准确性，通过多层级LLM Agent工作流确保了“谁在说话”的清晰界定，还为多音色合成奠定了坚实基础；同时，针对短文本合成不稳定的问题，创新性地结合Speech Token缓存与重复感知采样解码策略，有效改善了语气词和短对白的自然度与连贯性；而在效率方面，通过引入投机解码技术并适配vLLM批处理推理，在基本保持音质的前提下大幅提升了生成速度，实现了合成成本的大幅优化，真正支撑了海量网络小说内容的高效、低成本生产。

展望未来，我们将继续深化多模态技术在有声内容生成中的应用，探索更细腻的情感表达与个性化音色适配，进一步优化合成语音的表现力与自然度，同时持续推动推理效率的提升与成本的降低，以应对日益增长的用户需求，为用户带来更加沉浸、多样的听书体验，推动有声内容生态的不断演进与完善。
